# Размещение бота на BotHost: пошагово

## Как это работает (коротко)
Бот — это программа. Хостинг запускает её на сервере круглосуточно, поэтому компьютер можно выключать.
Вы кладёте код в **репозиторий** (папку на GitHub), BotHost забирает его оттуда, ставит библиотеки из `requirements.txt` и запускает `bot.py`.
Секреты (токен, ваш Telegram ID) хранятся **не в коде**, а в настройках бота на BotHost.
Данные учеников (файл `bot.db`) лежат на отдельном постоянном диске `/app/data`: при обновлении кода они не пропадают.

## Шаг 0. Подготовка
1. **Остановите бота на компьютере** (Ctrl+C в окне с ботом). Один токен может обслуживать только один запущенный экземпляр: пока бот работает дома, на хостинге будет ошибка `Conflict: terminated by other getUpdates request`.
2. **Тариф.** По описанию на сайте BotHost, на бесплатном тарифе данные стираются при перезапуске, а постоянный диск и переменные окружения есть на платных тарифах (Basic, Pro). Наш бот хранит всех учеников в базе, поэтому нужен платный тариф. Если не уверены, какой у вас, посмотрите в личном кабинете.
3. Держите под рукой **токен** (от @BotFather) и **свой Telegram ID** (число, его пришлёт бот @userinfobot).

## Шаг 1. Что загружать в репозиторий
В **корень** репозитория (не в подпапку!) кладутся файлы из этого архива:

| Файл | Зачем |
|---|---|
| `bot.py` | сам бот (главный файл) |
| `db.py` | база данных и игровая логика |
| `requirements.txt` | список библиотек: хостинг установит их сам |
| `questions.xlsx` | стартовый набор вопросов и памяток |
| `.gitignore` | защита: не даёт случайно загрузить токен и базу |
| `settings.env.example`, `README.md`, `DEPLOY.md` | подсказки (можно не загружать) |

**Никогда не загружайте:** `settings.env` (там токен), `bot.db` (данные учеников), папки `__pycache__`, `venv`. Если файлов `settings.env` и `bot.db` у вас в папке нет, это нормально: так и должно быть.

## Шаг 2. Репозиторий на GitHub без командной строки
1. Зайдите на github.com → **+** (справа вверху) → **New repository**.
2. Название: `english-quest-bot`. Видимость: **Public** проще всего. В нём нет ни токена, ни данных учеников, только код и учебные вопросы. Если хотите **Private**, понадобится дополнительно дать BotHost доступ, инструкция: https://bothost.ru/docs/git-repository-access
3. Галочки «Add a README», «.gitignore», «license» **не ставьте** → **Create repository**.
4. На открывшейся странице нажмите ссылку **«uploading an existing file»**.
5. Распакуйте архив на компьютере и **перетащите в окно браузера сами файлы** (не папку целиком, иначе всё окажется во вложенной папке и BotHost не найдёт `bot.py`). Файл `.gitignore` скрытый: если проводник его не показывает, включите «Показывать скрытые файлы» либо загрузите его отдельно.
6. Внизу нажмите **Commit changes**.
7. Проверьте: на главной странице репозитория сразу видны `bot.py`, `db.py`, `requirements.txt` (а не одна папка).

Адрес для BotHost: `https://github.com/ВАШ_ЛОГИН/english-quest-bot.git`

## Шаг 3. Создание бота на BotHost
Откройте страницу создания бота (bothost.ru → «Мои боты» → «Добавить бота») и заполните:

| Поле | Что указать |
|---|---|
| Название | любое, например «English Quest» |
| Платформа | Telegram |
| Библиотека | aiogram |
| Bot Token | токен от @BotFather |
| Git URL | адрес репозитория из шага 2 |
| Ветка | `main` |
| Главный файл (в «Дополнительных настройках») | можно оставить пустым (BotHost найдёт `bot.py`) или написать `bot.py` |

**Переменные окружения** (раздел «Переменные окружения», «Добавить переменную»):

| Ключ | Значение | Обязательно |
|---|---|---|
| `TEACHER_IDS` | ваш Telegram ID, например `123456789` | **да** |
| `TIMEZONE` | `Europe/Amsterdam` | желательно |
| `DAY_START_HOUR` | `5` | по желанию |

Токен хостинг передаёт боту сам (переменная `BOT_TOKEN`), путь к постоянному диску тоже (`DATA_DIR=/app/data`): бот сам кладёт базу в `/app/data/bot.db`.

Нажмите «Создать бота» и следите за логом сборки.

## Шаг 4. Проверка, что всё хорошо
В **логах работы** (не сборки) должны появиться строки:

```
База данных: /app/data/bot.db
Учителя (TEACHER_IDS): [ваш id]
Из questions.xlsx загружено вопросов: 40, памяток: 5
Бот запущен. Остановить: Ctrl+C
```

Главное — **путь базы начинается с `/app/data/`**. Если там `/app/bot.db` или просто `bot.db`, база пропадёт при обновлении: проверьте, что бот создан на платном тарифе, и напишите в поддержку BotHost (@bothostru).

Затем в Telegram откройте бота и нажмите `/start` **со своего аккаунта**: появится меню учителя. Если вместо него бот предлагает придумать никнейм, значит, `TEACHER_IDS` не задан или указан неверно (исправьте переменную, перезапустите бота и нажмите `/start` ещё раз).

## Шаг 5. Если ученики уже были на компьютере: перенос данных
Пропустите, если до этого были только тестовые ученики и можно начать с чистой базы.
1. Убедитесь, что бот на компьютере остановлен.
2. В панели BotHost **остановите** бота.
3. Откройте **файловый менеджер** бота → папка **`data`** → загрузите свой файл `bot.db` с компьютера (он лежит рядом с `bot.py`).
4. Запустите бота и проверьте «👥 Ученики»: все на месте.
Не запускайте после этого бота дома с тем же токеном.

## Шаг 6. Как обновлять бота
- **Код.** Заменили файл в репозитории (на GitHub: «Add file» → «Upload files», файлы с тем же именем заменятся) → в панели BotHost нажмите «Обновить из Git» (на платных тарифах может обновляться автоматически при изменении репозитория). Данные учеников в `/app/data` при этом сохраняются.
- **Вопросы и памятки.** Обновляйте **отправкой файла `.xlsx` боту в Telegram** (с учительского аккаунта), а не через репозиторий. Файл `questions.xlsx` из репозитория читается только при самом первом запуске (пока в базе нет вопросов), чтобы перезапуск не откатывал ваши правки. Если хотите наоборот, чтобы файл из репозитория применялся при каждом запуске, добавьте переменную `IMPORT_QUESTIONS_ON_START` со значением `always`.
- **Перед обновлением** нажмите «📊 Сводка» → «💾 Резервная копия базы».

## Шаг 7. Резервные копии
«📊 Сводка» → **«💾 Резервная копия базы»** (или команда `/backup`): бот пришлёт файл со всеми учениками, прогрессом и журналом ответов. Сохраняйте его раз в неделю и перед обновлениями (например, в «Избранное» в Telegram).
Восстановление: остановить бота → файловый менеджер → папка `data` → заменить `bot.db` присланной копией (переименовав её в `bot.db`) → запустить.

## Шаг 8. Если что-то не работает
| Симптом | Причина и решение |
|---|---|
| Бот молчит, в логе `Conflict: terminated by other getUpdates request` | Где-то ещё запущен бот с этим токеном (чаще всего на компьютере). Остановите его. |
| В логе `Не найден BOT_TOKEN` или `Unauthorized` | Токен не указан или указан неверно: исправьте в настройках бота. Токен вида `123456:ABC...`, без кавычек и слова `bot`. |
| `ModuleNotFoundError` или «не найден bot.py» | Файлы оказались во вложенной папке. Перенесите их в корень репозитория или укажите путь в поле «Главный файл», например `english-quest-bot/bot.py`. |
| Вместо меню учителя бот просит никнейм | Не задан `TEACHER_IDS`. Задайте, перезапустите, нажмите `/start`. |
| Контейнер постоянно перезапускается (`restarting`) | Откройте логи работы: в последней строке traceback будет причина. Пришлите её мне или в поддержку BotHost. |
| Ученики пропали после обновления | База писалась не в `/app/data`. Смотрите шаг 4 и восстановите из резервной копии. |

## Альтернатива без GitHub: загрузка архивом
Если с репозиторием не получается, BotHost принимает архив (по описанию в документации, на тарифах Basic и Pro): в профиле включите «Загрузка бота из архива», на странице «Мои боты» нажмите «Загрузить из архива» и выберите `.zip` с файлами **в корне** (наш архив уже собран так). Токен и переменные указываются в мастере загрузки. Обновление: «залить новый архив» на карточке бота, данные в `/app/data` сохраняются. Подробности: https://bothost.ru/docs/upload-bot-archive
